# План решения

Рабочая формулировка: **сравнение DDIM, DPM-Solver++ 2M и Heun (EDM) и подбор расписания уровней шума на CIFAR-10**.

Модель одна и заморожена: `google/ddpm-cifar10-32`. Обучения нет. Меняются сэмплер и сетка шагов.

PixArt-α в этом плане **не делается**, пока не закрыт обязательный объём.

Предыдущий обзор лежит в `docs/archive/`. Формулы, которые там «были в документе», здесь выписаны явно: `docs/methods.md`.

## Инварианты, которые нельзя ломать

1. Параметры шума только из конфига модели: `T=1000`, linear β от `1e-4` до `0.02`, `clip_sample=true` в чекпоинте.
2. Два режима нельзя смешивать:
   - **MATCH** — повторить поведение выбранного scheduler Diffusers, включая его clip/threshold по умолчанию.
   - **RESEARCH** — без внутреннего clip/threshold; финальный `clamp[-1, 1]` только при сохранении картинки.
3. Сначала MATCH по каждому сэмплеру, потом RESEARCH-сравнение.
4. Сравнивать **NFE** (вызовы U-Net на одно изображение), не `num_inference_steps`.
5. Heun: `NFE = 2K − 1` при `K` положительных уровнях. Отсюда бюджеты **9 / 19 / 39**.
6. Общий начальный шум `z ~ N(0, I)` хранится в **DDPM x-координатах**. В y-координаты переводится явно, см. `docs/methods.md`.
7. Нерегулярную сетку не подсовывать в `DDIMScheduler.timesteps`: у Diffusers `prev_timestep` считается через фиксированный шаг. Свои сетки — только свои пары `(t, t_next)`.
8. После просмотра тестовых шумов параметры не подкручивать.

## Что должно оказаться в конце

- Три своих сэмплера и JSON сверки с Diffusers.
- Таблица MSE/времени при одинаковом NFE: 3 сэмплера × 2 сетки × 3 бюджета.
- Найденная сетка для DPM-Solver++ при NFE 19, журнал поиска, стоимость подбора.
- Перенос **правила** сетки в DDIM и Heun (у Heun 10 узлов, не 19).
- Анализ ранней / средней / поздней опоры.
- FID шести финальных конфигураций при NFE 19.
- Одинаковые шумы → сетки картинок, включая плохие случаи.

Исследовательский успех — не «победить по всем метрикам». Имеет ценность и отрицательный результат, если он измерен по этому протоколу.
