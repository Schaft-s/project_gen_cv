# Формулы и соглашения

Модель предсказывает **ε**. Изображения в `[-1, 1]`. Дискретные метки `t ∈ {0,…,999}`: `t=0` — почти чистое, `t=999` — почти шум.

## 1. VP-таблица модели

```
β_t = linspace(1e-4, 0.02, 1000)
α_t = 1 − β_t
ᾱ_t = cumprod(α)
```

DDPM-состояние:

```
x_t = √ᾱ_t · x₀ + √(1 − ᾱ_t) · ε
```

Оценка чистого изображения:

```
x̂₀ = (x_t − √(1 − ᾱ_t) · ε̂) / √ᾱ_t
```

EDM-уровень шума, связанный с той же ᾱ:

```
s_t = √((1 − ᾱ_t) / ᾱ_t)
```

Тогда `√ᾱ_t = 1 / √(1 + s_t²)` и `√(1 − ᾱ_t) = s_t / √(1 + s_t²)`.

## 2. Две системы координат

| | DDPM, `x` | EDM, `y` |
|---|---|---|
| смысл | то, что ест U-Net | `y = x₀ + s · ε` |
| связь | `x = y / √(1 + s²)` | `y = x / √ᾱ = x · √(1 + s²)` |
| старт из общего `z ~ N(0,I)` | `x_start = z` | `y_start = z · √(1 + s²)` на том же стартовом уровне |

**Нельзя** подавать один и тот же тензор в DDIM и Heun и считать начальные условия одинаковыми.

Общий шум в проекте хранится как `z` в x-координатах. Конвертация обязательна.

На MPS генератор `torch.Generator` для `randn` в Diffusers должен быть **CPU** — иначе `Expected a 'cpu' device type for generator but found 'mps'`. Тот же трюк использовать в своих скриптах, если шум создаётся через Diffusers.

## 3. Denoiser

U-Net всегда вызывается в x-координатах с целочисленным `t`.

```
x = y / √(1 + s²)
ε̂ = UNet(x, t(s))
D(y, s) := x̂₀ = y − s · ε̂
```

`t(s)` на основном протоколе — точная метка из таблицы, без интерполяции: уровни выбираем только из `{s_0,…,s_999}`.

На `s = 0` модель **не** вызывается.

Счётчик NFE оборачивает только вызов U-Net, не `scheduler.step`.

## 4. DDIM, `η = 0`

В x-координатах, явная пара `(t, t')`:

```
x̂₀ = (x_t − √(1 − ᾱ_t) · ε̂) / √ᾱ_t
x_{t'} = √ᾱ_{t'} · x̂₀ + √(1 − ᾱ_{t'}) · ε̂
```

Это уравнение (12) из DDIM при `η = 0`. Один переход = 1 NFE.

Эквивалент в y-координатах — шаг Эйлера:

```
d = (y − D(y, s)) / s = ε̂
y' = y + (s' − s) · d
```

Ловушка Diffusers: в `DDIMScheduler.step`

```
prev_timestep = timestep - num_train_timesteps // num_inference_steps
```

Поэтому подмена `scheduler.timesteps` на нерегулярную сетку **не** даёт нужные переходы. Для MATCH с Diffusers брать штатную leading-сетку. Для RESEARCH все пары `(t, t')` задавать самим.

При MATCH с `clip_sample=true` после `x̂₀` делается `clamp[-1, 1]`, как в Diffusers. Для RESEARCH clip выключен.

## 5. Heun, `S_churn = 0`

Работает в y-координатах. Алгоритм 2 из EDM / `HeunDiscreteScheduler` при `γ = 0`:

```
d  = (y − D(y, s)) / s
yE = y + (s' − s) · d
если s' > 0:
    d' = (yE − D(yE, s')) / s'
    y' = y + (s' − s) · (d + d') / 2     # 2 NFE
иначе:
    y' = yE                              # 1 NFE, без деления на 0
```

Если положительных уровней `K` и затем переход в 0, то `NFE = 2K − 1`.

Diffusers-детали для MATCH:

- sample в y-координатах;
- перед U-Net: `scale_model_input`: `x = y / √(1 + s²)`;
- `pred_original_sample = sample − s · ε̂`;
- `init_noise_sigma = √(s_max² + 1)`;
- внутренний массив `sigmas` у Heun **удвоен** (predictor/corrector как два шага цикла). Наш код зовёт U-Net внутри сэмплера дважды и считает NFE сам.

## 6. DPM-Solver++ 2M

Нужен **многошаговый** вариант второго порядка, не 2S. Ориентир Diffusers:

```
algorithm_type="dpmsolver++"
solver_order=2
solver_type="midpoint"
lower_order_final=True
final_sigmas_type="zero"
```

`solver_type="heun"` внутри этого класса — это не наш Heun/EDM.

Diffusers держит sample в **x-координатах**. Sigma там — EDM `s`, перевод:

```
α(s) = 1 / √(1 + s²)
σ(s) = s · α(s)
λ(s) = log α(s) − log σ(s) = − log s
```

Для `prediction_type=epsilon`:

```
x̂₀ = (x − σ(s) · ε̂) / α(s)
```

Это тот же `D`, записанный в x.

Шаг 1-го порядка (старт и терминальный переход к нулю):

```
h = λ(s') − λ(s) = log(s / s')
x' = (σ(s') / σ(s)) · x − α(s') · (e^{−h} − 1) · x̂₀
```

Для малых `h` брать `-expm1(-h)` вместо `exp(-h)-1`.

Шаг 2M midpoint. Пусть `m0 = x̂₀` на текущем шаге, `m1` — предыдущий, `h0` — предыдущий интервал `λ`:

```
r0 = h0 / h
D0 = m0
D1 = (m0 − m1) / r0
x' = (σ(s') / σ(s)) · x
     − α(s') · (e^{−h} − 1) · D0
     − 0.5 · α(s') · (e^{−h} − 1) · D1
```

Эквивалентно подстановке `D̃ = (1 + 1/(2r0)) m0 − (1/(2r0)) m1` в формулу 1-го порядка.

Правила:

- первый переход — 1-й порядок (истории нет);
- переход к `s=0` — 1-й порядок, в `log s` ноль не подставлять;
- при `len(timesteps) < 15` Diffusers с `lower_order_final=True` понижает порядок на последних шагах — **повторить это в MATCH**;
- историю `m` очищать в начале каждой генерации.

NFE = число положительных уровней `K`.

## 7. Стандартные сетки

Оба варианта заканчиваются переходом в 0. Крайний положительный уровень общий.

**Uniform.** Равномерно по исходной метке `t` модели, как leading DDIM: взять `K` убывающих меток из `{0,…,999}`.

**Karras.** В шкале `s`:

```
s_i = (s_max^{1/ρ} + i/(K−1) · (s_min^{1/ρ} − s_max^{1/ρ}))^ρ
ρ = 7
```

`s_max`, `s_min` — крайние значения из VP-таблицы для выбранного диапазона. Затем каждый `s_i` привязать к ближайшей метке `t` без повторов и с сохранением строгого убывания. Если после привязки узлов меньше `K` — пересобрать (жадно, с запретом занятых меток).

## 8. Подбор сетки

Параметризация относительно базы Karras. Три внутренние опоры на позициях примерно `0.25, 0.50, 0.75` нормированного индекса. Сдвиги в `log s`, на краях 0. Между опорами сдвиги линейно интерполируются и **добавляются** к базе. Нулевые сдвиги воспроизводят Karras.

Поиск: координатный спуск, три прохода со сдвигами `0.20, 0.10, 0.05`. На опору — два направления. Кандидат отвергается, если ломается порядок, вылезает из диапазона или после привязки к `t` меняется число узлов.

Критерий:

```
L(S) = mean_j || G_S(z_j) − G_ref(z_j) ||²
```

по float-тензорам в `[-1, 1]`, до PNG. `G_ref` — DDIM `η=0`, 1000 NFE, тот же `z`.

Перенос в Heun: не копировать 19 узлов, а вычислить ту же функцию сдвигов в `K=10` точках.

## 9. Протокол сверки с Diffusers

Для каждого сэмплера отдельно.

1. Собрать scheduler из **конфига модели**, не из дефолтов класса.
2. `set_timesteps(N)` и снять его `timesteps` / `sigmas`.
3. Один шаг: одинаковые `sample`, `t` и **замороженный** выход U-Net. Сравнить `prev_sample`. Допуск MATCH: `max|Δ| < 1e-5` в fp32.
4. Полная траектория на 4 шумах, 20 шагах: `max|Δ| < 1e-4`.
5. Записать фактические ошибки в JSON этапа.

Если сверка не проходит, исследовательские запуски не начинать.
