# Отчёт этапа 1 

  
**Окружение baseline:** Apple M5 Pro, MPS, PyTorch 2.14.1, Diffusers 0.32.2, transformers 4.57.6



## 1. Постановка

Замороженный U-Net предсказывает шум ε. Обучения нет. Меняются только алгоритм перехода между состояниями (сэмплер) и сетка уровней шума. Цель проекта в целом — реализовать DDIM (η = 0), многошаговый DPM-Solver++ второго порядка и Heun по схеме EDM, сверить их с Diffusers, сравнить стандартные расписания при одинаковом числе вызовов модели (NFE) и подобрать уровни шума сдвигом нескольких опор при сохранении порядка.

Этап 1 закрывает теорию, обвязку, baseline и планирование. Реализация своих сэмплеров и сравнение — содержание этапа 2 (см. §7).

## 2. Теоретическая база

Модель работает в дискретном VP-расписании: `T = 1000`, линейная β от `10⁻⁴` до `0.02`, `ᾱ_t = cumprod(1 − β)`. Состояние DDPM:

```
x_t = √ᾱ_t · x₀ + √(1 − ᾱ_t) · ε
```

Оценка чистого изображения из предсказания шума:

```
x̂₀ = (x_t − √(1 − ᾱ_t) · ε̂) / √ᾱ_t
```

Связь с нотацией EDM: уровень шума `s_t = √((1 − ᾱ_t) / ᾱ_t)`, тогда `√ᾱ = 1/√(1+s²)`. В координатах EDM состояние `y = x₀ + s·ε`, связь с DDPM: `y = x · √(1+s²)`, `x = y / √(1+s²)`.

Параметризации влияют на формулу шага:


| Параметризация   | Что предсказывает сеть | Как входит в шаг                                          |
| ---------------- | ---------------------- | --------------------------------------------------------- |
| ε (наш чекпоинт) | шум                    | через `x̂₀` или через `D(y,s) = y − s·ε̂`                 |
| x₀               | чистое изображение     | напрямую в формулу обновления                             |
| v (velocity)     | скорость               | линейная комбинация x и ε; в этом проекте не используется |




### 2.1. DDIM, η = 0

Детерминированный переход в x-координатах, один вызов сети на шаг (NFE = K):

```
x̂₀ = (x_t − √(1−ᾱ_t) ε̂) / √ᾱ_t
x_{t'} = √ᾱ_{t'} x̂₀ + √(1−ᾱ_{t'}) ε̂
```

В y-координатах тот же шаг — Эйлер: `d = ε̂`, `y' = y + (s' − s)·d`.

### 2.2. Heun (EDM, S_churn = 0)

Predictor–corrector в y-координатах. На каждом положительном уровне два вызова сети; последний переход к `s = 0` — один Эйлер (без деления на ноль). Поэтому при K положительных уровнях `NFE = 2K − 1`.

```
d  = (y − D(y,s)) / s
yE = y + (s' − s) d
y' = yE                          если s' = 0
y' = y + (s' − s) (d + d') / 2   иначе
```

Это не то же самое, что `solver_type="heun"` внутри DPM-Solver в Diffusers.

### 2.3. DPM-Solver++ 2M

Многошаговый метод 2-го порядка (midpoint) в x-координатах. Первый шаг и переход к нулю — первого порядка; дальше используется предыдущая оценка `x̂₀`. Бюджет: `NFE = K`. Ориентир настроек Diffusers: `algorithm_type=dpmsolver++`, `solver_order=2`, `solver_type=midpoint`, `final_sigmas_type=zero`.

Отличия трёх методов: DDIM — один Эйлер на шаг в x; Heun — корректор в y с удвоенным NFE на шаг; DPM-Solver++ 2M — многошаговая схема второго порядка с историей `x̂₀`, тоже в x.

## 3. Согласование модели и сэмплера

Чекпоинт: `prediction_type=epsilon`, `clip_sample=true`, размер 32×32, 3 канала. U-Net всегда вызывается в x-координатах с целочисленной меткой `t ∈ {0,…,999}`.

Обвязка:

1. На вход сети: зашумлённое `x` и метка `t`.
2. На выход: `ε̂`.
3. Для DDIM / DPM шаг строится через `x̂₀` (формула выше).
4. Для Heun состояние живёт в y; перед сетью `x = y / √(1+s²)`, denoiser `D(y,s) = y − s·ε̂`. При `s = 0` сеть не вызывается.
5. Общий стартовый шум `z ~ N(0,I)` хранится в x-координатах. Для Heun старт: `y = z · √(1+s_max²)`. Подавать один и тот же тензор в DDIM и Heun без пересчёта нельзя.
6. Счётчик NFE считает только forward U-Net, не арифметику шага.
7. На MPS генератор `torch.Generator` для Diffusers держится на CPU.

Два режима, которые нельзя смешивать в одном сравнении:

- **MATCH** — повторить scheduler Diffusers, включая clip `x̂₀` в `[-1, 1]`.
- **RESEARCH** — без внутреннего clip; `clamp[-1, 1]` только при сохранении PNG.

Нерегулярную сетку нельзя подставлять в `DDIMScheduler.timesteps`: в Diffusers `prev_timestep` считается через фиксированный шаг `T/N`. Свои сетки — только своими парами `(t, t')`.

## 5. План экспериментов

Оси сравнения:

1. **Качество** — FID, визуальная оценка на одинаковых шумах, MSE к длинной детерминированной опоре.
2. **Стоимость** — NFE (не `num_inference_steps`) и фактическое время генерации после прогрева.
3. **Отдельно** — время подбора расписания.
4. **Сопоставимость** — одинаковый NFE при сравнении сеток; одинаковый начальный шум при сравнении методов.
5. **Переносимость** — найденное правило сетки на новых шумах и на других сэмплерах.

Бюджеты NFE выбраны так, чтобы Heun укладывался целым числом уровней (`NFE = 2K − 1`):


| NFE | K для DDIM / DPM | K для Heun |
| --- | ---------------- | ---------- |
| 9   | 9                | 5          |
| 19  | 19               | 10         |
| 39  | 39               | 20         |


Матрица стандартных методов: 3 сэмплера × {uniform, Karras} × {9, 19, 39} = **18** конфигураций. Столько достаточно, чтобы увидеть зависимость от бюджета и типа сетки, и не раздувать FID на все 18 точек.

Подбор сетки: только DPM-Solver++ 2M, NFE 19, база Karras. Три внутренние опоры (~0.25 / 0.50 / 0.75 нормированного индекса), сдвиги в `log s` с сохранением порядка. Критерий — средний MSE к опоре DDIM η = 0 на 1000 NFE при том же `z`. Поиск на 32 шумах, выбор на 64, итоговая оценка на отложенных 256. Контроль: двигать только раннюю / среднюю / позднюю опору.

Гипотеза по траектории: ближе к чистому изображению шагов не хватает сильнее — мелкие детали и цвета «собираются» на малых σ, поэтому поздняя опора должна сдвигаться так, чтобы уплотнить шаги у слабого шума.

FID только для финальных 6 конфигураций: 3 сэмплера × {Karras, найденная сетка} при NFE 19.

Критерии успеха этапа 2: (а) численная сверка с Diffusers в допуске; (б) заполненная таблица MSE/времени при одинаковом NFE; (в) найденная сетка не хуже базы на отложенных шумах или честно измеренный отрицательный результат; (г) проверка переноса правила.

## 6. Метрики и протокол оценки


| Метрика      | Что измеряет                                 | Выборка / прогоны                    |
| ------------ | -------------------------------------------- | ------------------------------------ |
| NFE          | число forward U-Net на одно изображение      | счётчик вокруг сети                  |
| Время        | стена часов после прогрева, sync MPS         | медиана повторов; без загрузки весов |
| MSE к опоре  | `mean ‖G_S(z) − G_ref(z)‖²` в float `[-1,1]` | опора: DDIM-1000; test: 256 шумов    |
| FID          | расстояние распределений к CIFAR-10 test     | clean-fid, 2000 картинок             |
| Визуально    | классы и детали на одинаковых z              | сетка 8 шумов                        |
| Время поиска | отдельно от генерации                        | журнал кандидатов                    |


Банки шумов не пересекаются, один seed генератора:


| Набор     | Размер               | Назначение                          |
| --------- | -------------------- | ----------------------------------- |
| stability | 16                   | устойчивость опоры 250 / 500 / 1000 |
| search    | 32                   | кандидаты сетки                     |
| valid     | 64                   | выбор лучшего кандидата             |
| mse_test  | 256                  | итоговая MSE, один раз              |
| fid       | 2000 (из банка 5000) | FID                                 |


После просмотра `mse_test` и FID сетку не трогать. Сопоставимость: один и тот же `z` в x-координатах; одинаковый NFE; одинаковый decode `[-1,1] → uint8` для FID.

## 7. План этапа 2 (уже выполненный)

Ниже — программа этапа 2 в том виде, в каком она была намечена. К сдаче рубежа она **уже выполнена**; рядом с каждым шагом — что получилось по факту. 



### Шаг 1. Свои сэмплеры и сверка с Diffusers

**План.** Реализовать DDIM η = 0, Heun (EDM) и DPM-Solver++ 2M на PyTorch; для каждого — MATCH-сверку с Diffusers (один шаг при замороженном выходе сети и полная короткая траектория).

**Сделано.** Все три сэмплера реализованы. Сверка: DDIM и Heun — max abs ошибка 0 в fp32 на проверенных траекториях; DPM-Solver++ 2M — max abs около `2·10⁻⁶` при допуске шага `< 10⁻⁵` и траектории `< 10⁻⁴`. Фактический NFE на 18 RESEARCH-конфигурациях совпал с бюджетами 9 / 19 / 39.

### Шаг 2. Стандартные сетки при одинаковом NFE

**План.** Прогнать 18 конфигураций на 256 отложенных шумах: MSE к DDIM-1000, время, визуальные сетки.

**Сделано.** При NFE 19 MSE к опоре:


|                 | uniform | Karras       |
| --------------- | ------- | ------------ |
| DDIM            | 0.00622 | 0.01015      |
| DPM-Solver++ 2M | 0.00408 | **0.000751** |
| Heun            | 0.01543 | 0.00560      |


Главный вывод: при фиксированном NFE важнее выбор сэмплера и типа сетки. DPM + Karras заметно ближе к длинной траектории. Для DDIM лучше равномерная сетка по t; для DPM и Heun — Karras (кроме вырожденного Heun при NFE 9). DDIM и DPM при одном NFE близки по времени; Heun в несколько раз дороже из-за корректора.

### Шаг 3. Подбор уровней шума

**План.** Координатный спуск трёх опор в `log s` относительно Karras для DPM при NFE 19; минимизация MSE к DDIM-1000; контроли early / mid / late.

**Сделано.** Найденные сдвиги `δ = (−0.15, −0.15, +0.15)`: в первой половине σ чуть ниже базы (быстрее уходим из сильного шума), ближе к чистому изображению σ выше — шаги там чаще. Это совпало с гипотезой про поздний участок. MSE на search 32: `2.85·10⁻⁴`, на valid 64: `3.30·10⁻⁴`. На тесте 256: Karras `7.51·10⁻⁴`, found `6.53·10⁻⁴` (−13%). Поиск дешёвый: порядка 24 с на кандидатах, около 36 с вместе с valid и контролями. Полная тройка опор лучше сдвига любой одной.

### Шаг 4. Перенос правила и FID

**План.** Перенести не список из 19 меток, а функцию сдвигов в DDIM (K = 19) и Heun (K = 10); посчитать FID шести конфигураций при NFE 19.

**Сделано.** Правило переносится с тем же знаком: DDIM −9 % MSE, Heun −3 %, лидер не меняется. FID (2000 картинок, NFE 19):


|                 | Karras    | found     |
| --------------- | --------- | --------- |
| DDIM            | 40.15     | 39.33     |
| DPM-Solver++ 2M | **29.10** | **28.79** |
| Heun            | 31.39     | 30.86     |


Найденная сетка слегка снижает FID у всех трёх (~0.3–0.8) без смены порядка. Визуально при NFE 19 DPM уже близок к опоре DDIM-1000; DDIM на той же сетке заметно мыльнее.
